# secure-communitcation

BLG 478E Network Security homework for secure communication between Alice and Bob using a Key Distribution Center (KDC).

## Objective

This project implements the assignment workflow from `BLG478E-HW-Spring2026.pdf`:

1. Alice requests a session key from the KDC.
2. The KDC generates a fresh session key `Ks`.
3. The KDC sends `E(KA-KDC, Ks)` to Alice and a ticket `E(KB-KDC, Ks || IDA)` for Bob.
4. Alice decrypts `Ks`, computes `H(M)`, and sends Bob:
   - `TICKET || E(KB-KDC, Ks || IDA)`
   - `DATA || E(Ks, M || H(M))`
5. Bob decrypts the ticket, obtains `Ks`, decrypts the payload, recomputes `H(M)`, and verifies integrity.

The repository also includes two assignment-specific modes:

- `PLAINTEXT_MODE=1`: sends the payload without encryption for the baseline Wireshark screenshot
- `TAMPER_HASH=1`: flips 1 bit in `H(M)` before transmission for the integrity-failure screenshot

## Protocol Details

### Entities

- `KDC`: trusted third party sharing one master key with Alice and one master key with Bob
- `Alice`: initiates the protocol and sends the secure message
- `Bob`: receives the ticket and message, then performs integrity verification

### Keys And Data

- `KA_KDC`: Alice-KDC master key
- `KB_KDC`: Bob-KDC master key
- `Ks`: fresh session key generated by the KDC
- `M`: plaintext message, which must contain your student number
- `H(M)`: SHA-256 hash of the message

### Crypto Choices

- AES-256-CBC for confidentiality
- SHA-256 for integrity checking
- 32-byte random session key `Ks`
- 16-byte random IV prefixed to ciphertext before transmission
- hexadecimal encoding for binary values carried over sockets

## Student Number Requirement

The assignment requires the plaintext message `M` to contain your student number.

Update this line in `alice.cpp` before collecting screenshots:

```cpp
string student_no = "150210093";
```

## Report Scenarios

You need three runs for the report.

### 1. Baseline Transmission

Run Alice in plaintext mode:

```powershell
docker compose run --rm -e PLAINTEXT_MODE=1 alice
```

What this does:

- Alice still gets a session key from the KDC
- Alice sends the ticket to Bob
- the `M || H(M)` payload is sent as plaintext instead of AES-encrypted data

Use this run for:

- baseline Wireshark screenshot

In Wireshark, the payload should contain readable text such as:

```text
DATA_PLAIN||150210093 Network Sec.||...
```

### 2. Secured Transmission

Run the normal secure case:

```powershell
docker compose run --rm alice
```

What this does:

- Alice receives `Ks` from the KDC
- Alice encrypts `M || H(M)` with AES-256-CBC under `Ks`
- Bob decrypts and verifies the message

Use this run for:

- secured Wireshark screenshot
- KDC terminal screenshot
- Alice terminal screenshot
- Bob terminal screenshot
- copying real values into `report.tex`

### 3. Integrity Test

Run the tampered-hash case:

```powershell
docker compose run --rm -e TAMPER_HASH=1 alice
```

What this does:

- Alice computes `H(M)`
- Alice flips 1 bit in the hash before transmission
- Bob recomputes the hash locally
- Bob detects the mismatch and prints `Verification Failed`

Use this run for:

- integrity test screenshot in Bob's terminal
- tampered hash value for the report

## Wireshark Instructions

### Capture Filter

Before starting capture, use:

```text
tcp port 5000 or tcp port 5001
```

This is a capture filter.

### Display Filter

After packets are captured, you can refine the view with:

```text
tcp.port == 5000 || tcp.port == 5001
```

This is a display filter.

### Interfaces To Try

On Windows with Docker Desktop, try Docker-related adapters first:

- `vEthernet (Default Switch)`
- `vEthernet (WSL)` if present
- other Docker/Hyper-V related adapters

### What You Should See

For this project, the relevant traffic is:

- Alice to KDC on port `5000`
- KDC to Alice on port `5000`
- Alice to Bob on port `5001`

For the baseline run, the packet payload should show readable text.

For the secure run, the payload should show:

- `TICKET||...`
- `DATA||<hex ciphertext>`

and the plaintext should not be readable.

## If Host Wireshark Does Not See Docker Traffic

Docker Desktop may hide internal container traffic from the host adapter capture. If that happens, use `tcpdump` inside the Docker network and then open the saved `.pcap` file in Wireshark.

### Find The Docker Network

```powershell
docker network ls
```

Look for a network similar to:

```text
secure-communitcation_default
```

### Capture Inside Docker Network

```powershell
docker run --rm --net secure-communitcation_default -v ${PWD}:/out nicolaka/netshoot tcpdump -i any -w /out/capture-secure.pcap "tcp port 5000 or tcp port 5001"
```

In another terminal, run the desired scenario:

```powershell
docker compose run --rm alice
```

Stop `tcpdump` with `Ctrl+C`, then open `capture-secure.pcap` in Wireshark.

Repeat this for:

- baseline capture
- secure capture
- tamper capture if needed

## Troubleshooting

### Source Changed But Output Still Shows Old Student Number

Rebuild the image:

```powershell
docker compose down
docker compose build --no-cache
```

### Wireshark Says There Is A Syntax Error

You are probably entering a display filter into the capture-filter box.

Use:

- capture filter:
  ```text
  tcp port 5000 or tcp port 5001
  ```
- display filter:
  ```text
  tcp.port == 5000 || tcp.port == 5001
  ```

### Wireshark Shows Unrelated Traffic

If you mostly see `QUIC`, `TLS`, `ARP`, `SSDP`, or traffic on ports unrelated to `5000` and `5001`, you are capturing the wrong interface or Docker traffic is hidden from the host.

Use the Docker-network `tcpdump` method described above.

### Docker Access Errors On Windows

If Docker commands fail because of local permission or config issues, make sure:

- Docker Desktop is running
- your user can access Docker
- `C:\Users\<your-user>\.docker\config.json` is readable
